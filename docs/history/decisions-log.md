## รอบ 1 — Excel: mark ความแน่นอนของงาน

**คำขอ:** "อยากให้ mark ได้ว่า project หรือ task ไหนที่ต้องทำแน่ ๆ project ไหนที่อาจจะมีโอกาสไม่ต้องทำ เพื่อที่จะได้วางแผนได้ดียิ่งขึ้น"

| คำถาม | คำตอบ |
|---|---|
| mark ระดับไหน | **ทั้งสองระดับ** — ตั้งที่โปรเจค แล้ว override ราย task ได้ |
| กี่ระดับ | **2 ระดับ**: แน่นอน / อาจไม่ทำ |
| คำนวณยังไง | **เทียบ 2 ฉาก**: ถ้าทำทุกอย่าง vs เฉพาะที่ยืนยันแล้ว |

**ผล:** Excel v2 + แนวคิด `OVER` (ล้นแม้ตัดงานไม่ชัวร์) vs `เสี่ยง` (ล้นเฉพาะถ้าทำทุกอย่าง) → SPEC BR-35–37, BR-40

## รอบ 3 — ขยาย requirement

- "อยากให้ใส่เรื่อง **ลาพักร้อน** เข้าไปได้ด้วย" → วันลาอยู่ใน MVP; **วันลาลด capacity ไม่ลดงาน** (BR-42)
- "plan **ต่อเนื่องแบบไม่มีขอบ** อยากทำแบบ Asana ที่ใช้ง่ายกว่า สามารถวางแผน**รายสัปดาห์และรายวัน**ให้เชื่อมโยงกันได้ง่าย และ**จำแนกแผนเป็น project** ได้ง่าย" → timeline ต่อเนื่อง, WEEK/DAY resolution (BR-20–25)
- "assignment ควรเป็น **task ย่อย ๆ**" → task ซ้อนชั้น
- "**ไม่ต้องมี actual vs plan** อันนี้ใช้สำหรับวางแผนโดยเฉพาะ" → ไม่มี time tracking

**การตัดสินใจเชิงออกแบบ:** หน่วยภายในเป็น person-day (ไม่ใช่สัดส่วน) เพราะสัดส่วนกำกวมเมื่อสัปดาห์ไม่เต็ม 5 วัน

## รอบ 4 — Positioning

- "**ไม่ต้องมี approval workflow** — มองว่ามันเป็นเว็บสำหรับจัดการวางแผน task **เหมือน Asana แต่ใช้ง่ายกว่า**ไปเลย"

**ผล:** ระบบนี้แทน Asana ไม่ใช่ชั้นเสริม · ไม่มี approval ทุกชนิด · หลักการ "ง่ายกว่า" (SPEC §1.3, โดยเฉพาะ P7 ไม่มี custom field/automation) · มีมุมมองลิสต์ · ติ๊กเสร็จได้แต่ไม่มี status หลายขั้น

## รอบ 5 — Requirement สำหรับ Claude Code (ฉบับปัจจุบัน)

**คำขอ:** "อยากสร้าง **client**, สร้าง **project** (สามารถ note หรือทำพวก **project charter** ได้ด้วย **เหมือน Notion**), สร้าง**พนักงานกำหนดตำแหน่ง**, และสามารถวางแผนรายโปรเจค โดยแต่ละ task มี**พนักงานได้มากกว่า 1 คน** ... สามารถวาง **milestone** สำคัญได้ด้วย และวางแผนได้ทั้ง**รายสัปดาห์และรายวัน** โดยต้อง**กรอกง่ายลบง่าย** และมีเมนูที่สามารถดู **workload หรือ task รายคน**ได้"

| คำถาม | คำตอบ | ผลใน SPEC |
|---|---|---|
| บริษัทเดียวหรือหลายบริษัท | "บริษัทเดียว แต่อยากแยกตำแหน่ง เช่น **worker จะเห็นแผนแค่ใน project ที่ตัวเองโดน invite เข้าไปหรือมีส่วนร่วม**" | single workspace + §3 สิทธิ์, BR-60 auto-invite เมื่อถูกมอบหมาย |
| Deploy | **Self-host ด้วย Docker** | §10 |
| Login | "phase นี้ พอ **manager สร้างพนักงานแล้ว ให้กำหนดรหัสผ่าน**สำหรับพนักงานแต่ละคน แล้วพนักงานเข้าระบบด้วยรหัสนั้นได้เลย" | Better Auth email+password + admin plugin, ไม่มี signup, FR-201–206 |

**ข้อความเพิ่มระหว่างเขียน:**
- "เวลาทำพวก project charter อยากให้**สร้างตาราง สร้าง page แปะภาพได้เหมือน Notion เลย**" → FR-502 หน้าซ้อนหน้า, FR-523–524 ตาราง + paste จาก Excel, FR-525–526 paste/ลากรูป
- "อยากทำให้มันเป็นเหมือน **working OS ของทีม**" → wiki ทีม (`WORKSPACE` space), หน้าหลัก `/home`, `Cmd+K` ค้นทุกอย่าง, sidebar แบบ Notion

**สิ่งที่กลับทิศจากรอบก่อน:**
- Milestone: รอบ 4 ตัดออก → รอบ 5 **ใส่กลับ** แบบเรียบง่าย (หมุดวันที่ + ผูก task + เตือนเลยกำหนด)
- Section ในโปรเจค: รอบ 3–4 มี → รอบ 5 **ตัดออก** ใช้ task แม่แทน (SPEC D8)
- Approval ของวันลา: รอบ 3 อยู่ Phase 2 → รอบ 5 **ไม่มีเลย** (SPEC §1.4)
- จำนวน concept ≤ 7: รอบ 4 เป็นกฎ → รอบ 5 **ยกเลิกกฎตัวเลข** (เอกสาร + milestone ทำให้เกิน) แต่คงหลักการ P7
